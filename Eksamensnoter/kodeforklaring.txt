KODE:

Person uden __str__ – standardadfærd

class Person:
    def __init__(self,name):
        self.name = name

p = Person("Josefine")
print(p)

Talepapir:
“Her har jeg en meget simpel klasse, Person, som kun har en constructor og et navn.
Når jeg printer objektet, får jeg ikke navnet, men en standard-repræsentation med typen og en hukommelsesadresse.
Det skyldes, at Python’s print()-funktion kalder str(obj), og når __str__ ikke er defineret, falder Python tilbage på objektets standard __repr__.
Det her viser, at selv noget så simpelt som print() er koblet direkte til datamodellen.”

Nøglepointe (sig gerne eksplicit):
Print er ikke magi – det er et metodekald i datamodellen.

Person med __str__ og __repr__
class Person:
    def __init__(self, name):
        self.name = name

    def __str__(self):
        return f"Person({self.name})"

    def __repr__(self):
        return f"<Person name={self.name}>"

p = Person("Josefine")
print(p)
print(repr(p))

Talepapir

“Her har jeg tilføjet to dunder-metoder: __str__ og __repr__.
__str__ bruges til en læsbar strengrepræsentation, typisk til brugeren, mens __repr__ er en mere teknisk repræsentation, som er nyttig til debugging.
Når jeg kalder print(p), bruger Python str(p), som igen kalder __str__.
Når jeg kalder repr(p) direkte, kaldes __repr__.
Det her er et godt eksempel på, hvordan vi kan styre Python’s standardfunktioner ved at implementere de rigtige metoder i datamodellen.”

Nøglepointe:
Vi binder vores egen klasse direkte ind i Python’s syntaks og built-in funktioner.

Operator overloading – Vector og __add__

class Vector:
    def __init__(self, x, y):
        self.x = x                  # Gemmer x-koordinaten i objektet
        self.y = y                  # Gemmer y-koordinaten i objektet

    def __add__(self, other):
        # Definerer, hvordan + operatoren skal virke mellem to Vector-objekter
        # Returnerer et nyt Vector-objekt med summerede koordinater
        return Vector(self.x + other.x, self.y + other.y)

    def __repr__(self):
        # Returnerer en strengrepræsentation af objektet til debugging / print
        return f"Vector({self.x}, {self.y})"


v1 = Vector(1, 2)       # Opretter en Vector med x=1, y=2
v2 = Vector(3, 4)       # Opretter en Vector med x=3, y=4
v1 + v2                 # Kalder v1.__add__(v2) → returnerer Vector(4, 6)


Talepapir:
“I Python er operatorer som + ikke hårdkodede til bestemte typer.
Når jeg skriver v1 + v2, oversætter Python det til et kald på v1.__add__(v2).
Ved at implementere __add__ kan jeg selv definere, hvad addition betyder for mine egne objekter.
Her betyder det, at to vektorer lægges sammen koordinatvist.
Det her kaldes operator overloading og er en central del af Python’s datamodel.”

Nøglepointe:
Operatorer er bare syntaktisk sukker oven på dunder-metoder.

Hvad sker der bag kulisserne?
v1 + v2
Python oversætter + til et metodekald:

v1.__add__(v2)

__add__ metoden laver en ny Vector med summerede koordinater:
x = 1 + 3 = 4
y = 2 + 4 = 6

Python får det nye Vector-objekt

Iterator-protokollen – Counter

class Counter:                          # Definerer en klasse ved navn Counter
    def __init__(self, limit):          # Constructor, kaldes når et Counter-objekt oprettes
        self.limit = limit              # Gemmer den øvre grænse for tælleren
        self.current = 0                # Starter tælleren ved 0 (intern tilstand)

    def __iter__(self):                 # Gør objektet itererbart
        return self                     # Returnerer sig selv som iterator

    def __next__(self):                 # Kaldes for at få næste værdi i iterationen
        if self.current < self.limit:   # Tjekker om vi stadig er under grænsen
            self.current += 1            # Øger tælleren med 1
            return self.current          # Returnerer den næste værdi
        raise StopIteration              # Stopper iterationen, når grænsen er nået

for number in Counter(3):                # Opretter et Counter-objekt og starter et for-loop
    print(number)                        # Printer hver værdi, som __next__ returnerer


Talepapir
“Iteration i Python fungerer via iterator-protokollen, som består af __iter__ og __next__.
Når for-loopet starter, kalder Python iter(obj), som igen kalder objektets __iter__-metode.
Derefter kalder Python gentagne gange __next__ for at få næste værdi.
Når __next__ rejser StopIteration, ved Python, at løkken skal stoppe.
På den måde kan vores egen klasse fungere i et for-loop på præcis samme måde som en liste eller en range.”


Hvad betyder det, at __iter__ returnerer et iterator-objekt?
Når man siger, at __iter__ returnerer et iterator-objekt, betyder det:
- Det returnerer et objekt, som Python kan hente værdier fra én ad gangen ved hjælp af __next__.
Et iterator-objekt er altså et objekt, der:
- har en __next__-metode
- ved, hvor langt man er kommet i gennemløbet
- kan signalere, hvornår der ikke er flere elementer (StopIteration)


Nøglepointe:
For-loops virker ens for alle objekter, der følger iterator-protokollen.

Container-protokollen – MyList

class MyList:                              # Definerer en ny klasse ved navn MyList
    def __init__(self, items):             # Constructor, kaldes når et MyList-objekt oprettes
        self.items = items                 # Gemmer den liste, vi vil “wrappe”, som attribut

    def __len__(self):                     # Definerer opførsel for len(obj)
        return len(self.items)             # Returnerer længden af den indre liste

    def __getitem__(self, index):          # Gør objektet indekserbart (obj[index])
        return self.items[index]           # Returnerer elementet fra den indre liste

    def __contains__(self, value):         # Gør “value in obj” muligt
        return value in self.items         # Tjekker om værdien findes i den indre liste


ml = MyList([1, 2, 3])                     # Opretter et MyList-objekt med items [1,2,3]

print(len(ml))                             # Kalder ml.__len__(), output: 3
print(ml[1])                               # Kalder ml.__getitem__(1), output: 2
print(2 in ml)                             # Kalder ml.__contains__(2), output: True


Talepapir:
“Her har jeg lavet en klasse, der opfører sig som en container.
Ved at implementere __len__, __getitem__ og __contains__ kan objektet bruges med len(), indeksering og in-operatoren.
Når jeg skriver len(ml), kalder Python ml.__len__(), og når jeg skriver 2 in ml, kalder Python ml.__contains__(2).
Det her viser igen, hvordan Python’s syntaks er koblet direkte til datamodellen.”

Nøglepointe:
Hvis et objekt implementerer de rigtige metoder, behandles det som en liste – uanset typen.

Hvad sker der bag kulisserne?
len(ml)
- Python oversætter til ml.__len__()
- Returnerer længden af den indre liste (len([1,2,3]) → 3)
ml[1]
- Python oversætter til ml.__getitem__(1)
- Returnerer elementet med indeks 1 i den indre liste → 2
2 in ml
- Python oversætter til ml.__contains__(2)
- Tjekker om 2 findes i den indre liste → True

Hvilken protokol implementerer vi her?
Dette er container-protokollen i Python:
- __len__ → gør objektet “målbart”
- __getitem__ → gør objektet indekserbart og iterable
- __contains__ → gør objektet søgbart med in
Når et objekt implementerer disse tre, kan det opføre sig som en almindelig Python-liste.
En Python-liste er en indbygget datatype, der kan indeholde flere elementer, i rækkefølge, som kan ændres.
Eksempel:
lst = [1, 2, 3, "hej"]
